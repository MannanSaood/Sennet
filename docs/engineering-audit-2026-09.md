# Sennet engineering audit — 2026-09-08

## Assessment and scope

Sennet is currently a network-observability prototype, not a production multi-tenant observability platform. The inspected product has real agent/control-plane code, but multiple user-facing features are fixtures, disconnected implementations, or stubs. No measured evidence establishes a sustainable ingestion rate, retention capacity, query latency, availability, or agent overhead. A successful build alone cannot establish readiness.

This audit covers the Go backend, Rust agent and eBPF sources, React application, protocol, installer/documentation, and test/release structure. Findings below are source-confirmed unless described as risks or missing evidence. Linux kernel execution, cloud account integrations, authenticated browser journeys, security penetration testing, and distributed load/failure tests are not validated by this Windows audit. It would be misleading to claim every possible defect has been found.

## Findings and remedies

P0 = blocks shared production use; P1 = broken core behavior or scale prerequisite; P2 = product/operational gap. “Fixed” refers only to the narrow change described, not the entire surrounding feature.

| ID | Priority | Evidence and impact | Solution / acceptance criterion |
|---|---|---|---|
| SEC-01 | P0 | `backend/handler/key_handler.go` lists all raw keys; Firebase authentication does not scope the query. Any accepted dashboard identity reaches global key listing. | Introduce organization/workspace principals and server-side scope checks; hash credentials, return secrets once, list metadata only. Two-tenant adversarial tests must prevent read/create/revoke across tenants. Open. |
| SEC-02 | P0 | `backend/db/db.go` has optional owners but heartbeat registration does not bind an agent to the authenticated key owner. Stats, cloud configs, costs and recommendations are global. | Bind tenant identity at authentication, not from payload. Require it in all repository/query methods, caches, streams, background jobs and storage keys. Block shared deployment until isolated. Open. |
| SEC-03 | P1 | `ValidateAPIKey` ignored `expires_at`, unlike signature validation. | Fixed: both paths reject expired keys; regression test added. Rotation remains non-transactional and loses owner metadata. |
| SEC-04 | P1 | `backend/middleware/ratelimit.go` trusts arbitrary X-Forwarded-For/X-Real-IP. Combining IP and unvalidated Authorization permits new buckets by varying credentials. | Trusted proxy allowlist; pre-auth source limiter plus post-auth tenant quotas; bounded bucket cardinality and lifecycle; test spoofing and NAT fleets. Open. |
| SEC-05 | P1 | `signature.go` reads an unbounded body before route auth/rate limiting. Optional signing can be skipped by omitting one header. Timestamp permits replay inside five minutes; method/path are not signed. | Bound compressed and decoded requests before body access; reject partial signatures; protocol-versioned method/path/body/nonce binding or standard workload mTLS. Test oversized bodies and duplicate delivery separately. Open. |
| SEC-06 | P1 | `cloud_configs.config_json` stores credentials; handler calls JSON serialization and DB persistence directly. Encryption utility is not wired into this path. Its key loader pads/truncates arbitrary key material. | Prefer role/workload identities and secret-manager references; envelope encryption with versioned KMS keys; strict key length; safe migration of existing configs. Open. |
| SEC-07 | P1 | Startup logged an initial API-key prefix. A Firebase-admin credential-shaped file is untracked in the root. | Fixed prefix logging and added credential filename ignore rule. File contents were not read. Ignore rules do not prove a credential was never shared; provenance remains unverified. |
| SEC-08 | P2 | Public `/debug` and `/metrics`; broad CORS defaults; no applied role checks on key routes. | Separate internal management listener, configurable origins, role-scoped operations and structured audit events. Open. |
| DATA-01 | P1 | `StatsHandler` owns independent zero-initialized counters; neither Heartbeat nor another production caller updates it. Open. |

Bound label cardinality; expire stale agents; distinguish cumulative counters, deltas and rates. Open. |
| DATA-03 | P1 | Heartbeat acknowledged success after a DB write failure; accepts empty agent identity. | Fixed: reject empty/oversized identity/version and return unavailable on persistence failure. Regression tests added. Not a durable telemetry acknowledgement. |
| DATA-04 | P1 | `proto/sentinel/v1/sentinel.proto` only exposes heartbeat/control summaries; no spans, logs, flow stream or business events. | OTLP-compatible traces/logs/metrics; versioned domain events and authenticated streaming ingestion. Contract tests across Rust/Go/collector. Open. |
| DATA-05 | P1 | No durable agent spool, broker, replay offsets, consumer lag, dead-letter processing, deduplication, or explicit overload contract. | Bounded local WAL and durable regional log; at-least-once delivery with dedup rules, retry budgets, backpressure and measurable loss. Open. |

## Verification record

Initial web lint: **15 errors**, including conditional hook, impure render, unused variables, effect state updates, and mixed Fast Refresh exports. Initial sandboxed build/test attempts hit filesystem cache restrictions; they are environment failures, not product failures. Approved reruns and final results are recorded in `audit-validation.md`.

The targeted changes intentionally do not claim tenant isolation, live dashboards, distributed ingestion, or financial observability are implemented. Those remain release blockers. No production systems were deployed or cloud resources provisioned.
